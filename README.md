# AtlasSearch VM4

VM4 is the search/API/frontend component of AtlasSearch. This repository contains no VM1–VM3 implementation and does not rebuild distributed indexes. It consumes versioned Parquet exports produced by VM3.

## Current data contract

Each directory under `data/versions/<version>/` must contain:

- `documents.parquet`: `document_id`, `title`, `content`; optional `url` and metadata columns.
- `inverted_index.parquet`: `term`, `document_id`, `term_frequency`.
- `pagerank.parquet`: `document_id`, `pagerank`.

No VM3 exports or project manuals were present when this application was scaffolded. The loader therefore keeps this contract explicit and fails safely with actionable errors. Replace the local fixture with the actual export directory after VM3 confirms its schema.

## Run locally

From the repository root, create a Python environment and install dependencies:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
```

Put Parquet exports in `data/versions/v1.0.0/` (the test fixture can be generated by the test suite), then run:

```powershell
$env:ATLAS_DATA_DIR = "data/versions"
uvicorn backend.app.main:app --reload
```

In another terminal:

```powershell
cd frontend
npm install
npm run dev
```

Linux uses the same commands with `.venv/bin/activate` and forward slashes. Copy `.env.example` files to `.env` and configure paths externally. Do not place ZeroTier addresses in source code; add them only when the VM integration contract is supplied.

## API

`GET /`, `/health`, `/search?q=...&limit=10&offset=0`, `/documents/{id}`, `/stats`, and `/versions` are public read endpoints. `POST /admin/reload?version=<version>` is disabled unless `ATLAS_ALLOW_ADMIN_RELOAD=true`. Reload validates a new index before atomically swapping it, preserving the previous active index on failure. FastAPI also exposes `/docs`.

## Ranking

Queries use lowercase Unicode word tokens, retrieve candidates from the inverted index, calculate BM25 (`k1=1.2`, `b=0.75`), then normalize over the candidate set and combine `0.7 * BM25 + 0.3 * PageRank`. Missing PageRank contributes zero. The API exposes component scores for evaluation.

## Tests

```powershell
pytest -q
```

The suite covers Parquet loading, validation, tokenization, candidate retrieval, BM25, PageRank blending, API responses, and reload safety. Frontend build verification requires Node/npm and can be run with `cd frontend; npm install; npm run build`.

## VM integration checklist

1. Obtain VM3's authoritative export filenames, columns, tokenization rules, and version naming convention.
2. Map those exports into the configured `ATLAS_DATA_DIR` without changing application code where possible.
3. Confirm the VM3 preprocessing exactly matches `backend/app/search.py:tokenize`.
4. Test a real VM3 version on Linux VM4 over the mounted/shared storage path.
5. Configure CORS and any network restrictions for the deployed frontend.
